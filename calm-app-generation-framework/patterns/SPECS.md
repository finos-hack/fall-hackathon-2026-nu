# Pattern specifications (Pattern_Library v1)

Each pattern is a technology-neutral CALM 1.2 pattern JSON in this folder (`P<nn>-<name>.json`). It names roles, never products. Pattern metadata lists the related control rule IDs and risk rule IDs from `rule-authoring-framework/catalogs/`. The JSON files for P02 to P14 are generated by `scripts/build_patterns.py` from the table in that script, and P15 and P16 by `scripts/build_cyber.py` (through the Build Pattern path). They are reviewed, and published through `calm_generation.pattern_library.publish` (validate with `calm validate -p`, then human approval).

CALM_AI_Assets (`architecture-as-code/calm-ai/tools/pattern-creation.md`, `node-creation.md`, `metadata-creation.md`) are used as concepts only: `prefixItems` with `const` values for fixed parts, typed metadata properties for free parts, and `options` relationships for variation. Variation lives in the RA template (Composer), not in the patterns.

Node metadata uses the vocabulary in the header of `controls.catalog.yaml`. A property with `enum` is a closed choice; a property with `type` only is free text (and may be `UNMAPPED` in the Taxonomy).

Patterns that share a role (`agent` in P12, P13, P14, P15; `remediation-tool` and `tool` in P12 and P16 are merged the same way in RA05) contribute disjoint metadata properties to the same component. The Composer merges them per component and reports a conflict, naming both patterns, when the same property is defined differently.

The library also holds P17 New Pattern, a placeholder created from the dashboard Build Pattern page; it is not part of this table. P02 is at version 2 (description wording edited in the dashboard); its nodes and metadata are unchanged.
