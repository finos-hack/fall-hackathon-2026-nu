# Spike 1.1: CALM CLI
Reqs: 2.1, 2.2, 2.3, 2.4, 2.10. Script: `scripts/spike/calm_spike.sh` (run from platform root in Git Bash; writes inputs and raw outputs to `$OUT`, default `$TMPDIR/calm_spike`). The draft repo was not touched.

## Version
- `calm --version` = **1.60.1** (`@finos/calm-cli`, global npm), Node v24.11.0. Pin this version.
- Schemas load from the bundled `dist/calm/release/{1.0,1.1,1.2,...}`; no network needed for `$schema: .../release/1.2/meta/calm.json`.

## `calm validate -a <arch> -f json`
- stdout is JSON: `{jsonSchemaValidationOutputs[], spectralSchemaValidationOutputs[], hasErrors, hasWarnings}`. stderr carries `info/error [...]` log lines only, so parse stdout only.
- Each finding: `code, severity (error|warning), message, path, schemaPath, line_start, line_end, character_start, character_end, source ("architecture"|"pattern")`.
- **VALID = `hasErrors == false`**. Exit code 0 when no errors, 1 when `hasErrors`. Warnings alone exit 0; `--strict` makes warning-only exit 1. Do not use the exit code to decide validity; use `hasErrors`.
- Valid: both arrays empty, `hasErrors:false, hasWarnings:false`, rc 0.
- Warning-only (node not in any relationship): `spectralSchemaValidationOutputs` has `architecture-nodes-must-be-referenced` (severity `warning`, path `/nodes/<id>/unique-id`), `hasErrors:false, hasWarnings:true`, rc 0.
- Invalid: missing required `description` gives a `json-schema` error (path `/nodes/svc`, schemaPath `#/required`). A `connects` destination naming an unknown node gives spectral error `connects-relationship-references-existing-nodes-in-architecture` (path `/relationships/r1/relationship-type/connects/destination/node`). `hasErrors:true`, rc 1.

## `calm validate -p <pattern> -a <arch> -f json`
- Same output shape. Pattern findings have `source:"pattern"`; mismatches against the pattern are `json-schema` errors with `source:"architecture"`, e.g. `must NOT have fewer than 2 items` (schemaPath `#/properties/nodes/minItems`) and `must be equal to constant (expected {...})`.
- Matching arch: only the pattern lint warning `avoid-boolean-properties` (source `pattern`) appeared, so `hasErrors:false, hasWarnings:true`, rc 0. Pattern lint warnings (`pattern-nodes-must-be-referenced`, `avoid-boolean-properties`) can appear on the pattern itself.
- Patterns use `"$schema": ".../release/1.2/meta/calm.json"`. `.../meta/pattern.json` does NOT exist and fails with `Failed to load document from URL`.
- Patterns need top-level `nodes` and `relationships` (`pattern-has-nodes-relationships`); generate crashes with `Cannot read properties of undefined (reading 'prefixItems')` if `relationships` is missing.

## `calm generate -p <pattern> --option-choices <file> -o <out>`
- Run twice with `--option-choices` = `{}`: outputs are **byte-identical** (`cmp`: YES). stdout is empty; the log goes to stderr; rc 0.
- Placeholders: strings `"[[ NAME ]]"`, `"[[ DESCRIPTION ]]"` (upper-cased property name); booleans `"[[ BOOLEAN_FLAG ]]"` (a string, not a JSON boolean); integers `-1`; an unconstrained string node reference (`source.node`) `"[[ NODE ]]"`. `[[ REF_X ]]` was not observed in this pattern; the node reference gave `[[ NODE ]]`. Handle any `[[ ... ]]` string and `-1` as "unfilled".
- `const` values are emitted as-is. Output key order: `nodes, relationships, ..., $schema` (last), and `$schema` is set to the pattern's `$id`, not the CALM meta schema. Fill-in code must rewrite `$schema` before validating the result as an architecture.
- NOT tested: a pattern with `oneOf`/`options` using non-empty `--option-choices`. Test it in the task that needs options; this spike only confirms the `{}` case.

## Draft models and AI node types
- `customer-support-compliant.json` and `customer-support-gap.json` (use `node-type: "ai-agent"`, hyphen form, plus `actor`, `datastore`): both validate with **no findings**, `hasErrors:false`. So `node-type` is a free string.
- `node-type` `ai:agent`, `ai:llm`, `ai:tool`: **accepted** (no node-level error; only the orphan-node warning when unreferenced).
- Custom relationship verb (`relationship-type: {"invokes": {...}}`): **rejected**. `relationship-type` is a `oneOf` of `deployed-in`, `composed-of`, `interacts`, `connects`, ...; each branch reports `must have required property '<verb>'`, `hasErrors:true`.
- Fallback (validates clean): express the verb as `connects` plus `metadata`, e.g. `"metadata": {"verb": "invokes"}` on the relationship. Node-kind can also be kept in node `metadata` (`"ai-kind": "agent"`) with `node-type: "service"` if the `ai:*` types are ever rejected by a newer CLI.

## Contingency
CLI was available, so none was needed. If `calm` is unavailable, record the failure and treat validation as `unavailable`, not `valid`.
